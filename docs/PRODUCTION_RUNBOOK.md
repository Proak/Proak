# 每场景10阶段自查与退出条件

这是**每个** Lxx_Bxx 的标准工序；大型角色与模块资产可以跨场景复用。所有自动测试对美感只能提示风险，不可授予审美通关。

| Gate | 内容 | 自动检查 | 必须人工检查 | 不通过时 |
|---|---|---|---|---|
| G0 Canon / User Intent | 本段玩家目标、剧情证据、角色因果、机制归属 | JSON必需字段 / 版本检查 | 是否让剧情更可信？是否过度文学化？ | 退回叙事设计 |
| G1 Reference / Rights | 建筑真实参考3–5条、明确许可/仅视觉参考 | URL非空、资产台账必填 | 不复制辨识性设计 | 禁止开建 |
| G2 Greybox | 比例、布局、谜题、路径、检查点 | 静态场景规范 / 可达性脚本（未来） | 3名无指导玩家能找到路径 | 不许升高模 |
| G3 Gameplay | 互动、反馈、失败恢复、敌人线索、游戏化文档 | UE Functional Test / Smoke | 首次玩家是否懂规则 | 修机制而非补长文字 |
| G4 Mesh | Blender模型、UV、法线、尺寸、碰撞、实际用途 | bpy headless mesh audit / object manifest | 近中远三尺度辨识与制造逻辑 | 拒绝低质资产 |
| G5 Art Direction | 主要镜头、材质、主次、色彩与独特性 | 三机位固定截图对比 | 艺术总监盲看实际游戏画面 | 重做光/构图 |
| G6 Audio & Cinema | 空间音源、预兆、事件同步、低频动态 | 事件表 / 峰值检查（后续） | 戴耳机试听、无突兀音量 | 调导演和音频 |
| G7 Integration | UE导入、脚本和材质依赖、性能 | Automation / Gauntlet / 编译与导航测试 | 实机玩家操作与录屏 | 没跑不算过 |
| G8 Red-Team | 叙事、交互、风格去泛化 | 文本启发式lint，重复资产扫描 | 独立Agent批评 + 人类品鉴 | 必须修P0/P1 |
| G9 Playtest & Freeze | 陌生玩家完整流程、优化、Bug复测 | bug统计 / build version / QA证据校验 | 非作者试玩、节奏量表 | 禁止扩下一幕 |

## Gate的实证要求
- **BLOCKED**：环境或素材缺少；不能假装通过。
- **NOT_RUN**：没有执行，绝不等同PASS。
- **PASS**：具体测试名、时间、Git SHA、设备、报告路径、截图或录像路径；避免用语言模型主观打分替代物理验证。
- **P0阻断**：启动失败、崩溃、软锁、版权/隐私不明、剧情主线不能理解；零容忍。
- **P1需要解决**：谜题误解、AI敌人非因果行为、房间空壳、光影误导、严重掉帧、同声对白；修完复测。
- **P2**：小幅装饰、字幕停顿、次要纹理问题可排期。

## 阶段闸门（先小后大）
1. M0 设计锁定：世界规则/玩家动词/四大核心玩法/24段目标清单（纸面）
2. M1 技术贯通：UE5空项目运行，移动/互动/门/截图/日志/自动测试PASS
3. M2 15分钟灰盒：按 `production/vertical_slice_plan.json` 将 B01–B04 及 B07–B08 的玩法样本重编为14–17分钟（独立试验，非正式六幕时间线）；一谜题、一潜行、一追逐、一个安全区
4. M3 视觉基准间：门厅与走廊高保真，3镜头、真实空间声、合理预算、示范资产工艺
5. M4 垂直切片审美验收：真正12–18分钟游戏体验，陌生玩家观察反馈，角色/节奏整改
6. M5 六幕全部灰盒+锁主线，再分批做高保真
7. M6 Alpha：主线/支线/存档/字幕无软锁，自动测试可在真引擎执行
8. M7 Beta：多机型性能、独立试玩、艺术一致性、QA与版权清查
9. M8 Release Candidate：Steam申报、真实截图、发布检查、崩溃与回归证据

**禁止**：先用AI批量生成所有24段精美地图然后才玩；文档和概念图不得冒充可玩性证据。
